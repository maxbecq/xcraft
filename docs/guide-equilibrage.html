Guide de l'équilibreur

Créer un compte GitHub, modifier les statistiques des unités et lancer les 98 parties de test, sans rien installer et sans écrire de code.

Le principe en une ligne

Tu modifies les chiffres→ Tu proposes le changement→ Un robot joue 98 parties →Il commente le résultat→ Max valide et publie

Tout se passe dans le navigateur, sur le site GitHub. Tous les chiffres du jeu (PV, coûts, dégâts, portées, temps de production, comportement de l'IA) sont dans un seul fichier : balance.json. Tu ne peux rien casser : tant que Max n'a pas validé, le jeu en ligne ne change pas.

Sommaire

  1. Créer ton compte GitHub
  2. Accepter l'invitation de Max
  3. Modifier les statistiques
  4. Proposer le changement
  5. Lire le résultat des 98 parties
  6. Corriger ou compléter ta proposition
  7. Après validation : tester en jeu
  8. Ce que veut dire chaque chiffre

1Créer ton compte GitHub

GitHub est le site où est rangé le code du jeu. Le compte est gratuit.

  1. Va sur github.com/signup.
  2. Saisis ton adresse e-mail, choisis un mot de passe, puis un nom d'utilisateur (par exemple jean-equilibre). Ce nom sera visible des autres.
  3. Réponds au petit test anti-robot, puis clique sur Create account.
  4. GitHub t'envoie un code à 8 chiffres par e-mail : recopie-le sur la page.
  5. Les questions qui suivent (équipe, centres d’intérêt) sont facultatives : tu peux les passer avec le lien Skip en bas de page.
À faire ensuiteEnvoie ton nom d'utilisateur GitHub à Max : il en a besoin pour t'inviter sur le projet.

2Accepter l'invitation de Max

  1. Tu reçois un e-mail de GitHub : « maxbecq invited you to collaborate on maxbecq/xcraft ».
  2. Clique sur View invitation, puis sur Accept invitation.

E-mail introuvable ? Connecte-toi et ouvre directement github.com/maxbecq/xcraft/invitations. L'invitation expire au bout de 7 jours : passé ce délai, demande à Max de la renvoyer.

3Modifier les statistiques

  1. Ouvre github.com/maxbecq/xcraft/blob/main/src/balance.json.
    Garde ce lien dans tes favoris : c'est ton point d'entrée à chaque fois.
  2. En haut à droite du fichier, clique sur le crayon ✎ (bulle d'aide : Edit this file).
  3. Le fichier devient modifiable. Trouve l'unité : chaque ligne commence par son nom ("archer", "belluaire"…). Pour chercher, clique dans le texte puis utilise Ctrl+F (⌘+F sur Mac).
  4. Change seulement les nombres.

Exemple : l'Archer passe de 70 à 80 PV et sa portée de 5 à 5,5.

Avant :
"archer": { "hp": 70, "shield": 70, "armor": 1, "speed": 2.4, "sight": 9, "supply": 2, "cost": { "minerals": 150, "energy": 50 }, "buildTime": 24, "attack": { "damage": 10, "range": 5, "cooldown": 1.2 } },

Après :
"archer": { "hp": 80, "shield": 70, "armor": 1, "speed": 2.4, "sight": 9, "supply": 2, "cost": { "minerals": 150, "energy": 50 }, "buildTime": 24, "attack": { "damage": 10, "range": 5.5, "cooldown": 1.2 } },
Les 4 règles pour ne pas casser le fichier 1. Un point pour les décimales : 5.5, jamais 5,5.
2. Ne touche pas aux guillemets ", aux accolades { }, aux crochets [ ], aux deux-points ni aux virgules.
3. Ne renomme rien : "hp" reste "hp", "archer" reste "archer".
4. Un nombre sans guillemets : 80, pas "80". 
Erreurs fréquentes :
"hp": 80,5        ← virgule au lieu du point
"hp": "80"        ← guillemets autour du nombre
"range": 5.5 } }  ← virgule effacée avant l'accolade suivante

Si tu te trompes, pas de panique : le robot le détecte (étape 5), et tu peux corriger (étape 6). Pour tout annuler avant de valider, clique sur Cancel changes.

4Proposer le changement

  1. En haut à droite, clique sur Commit changes…. Une fenêtre s'ouvre.
  2. Commit message : décris ton changement en une phrase, par exemple Archer : 80 PV, portée 5.5.
  3. En bas de la fenêtre, coche Create a new branch for this commit and start a pull request.
    GitHub propose un nom de branche (jean-equilibre-patch-1) : tu peux le garder ou le remplacer, par exemple archer-plus-solide.
  4. Clique sur Propose changes.
  5. Sur la page suivante, relis le titre, ajoute si tu veux une explication (pourquoi ce changement, ce que tu as observé en jeu), puis clique sur Create pull request.
Ne choisis pas « Commit directly to the main branch »Cette option publie ton changement sans test ni validation. Choisis toujours la nouvelle branche.

Une pull request (« PR ») est une proposition de changement : elle reste en attente jusqu'à ce que Max la valide. C'est elle qui lance automatiquement les 98 parties de test.

5Lire le résultat des 98 parties

Juste après l'ouverture de la pull request, le test démarre tout seul. En bas de la page de la PR, une case indique où il en est :

Tu voisÇa veut dire
● jaune Some checks haven't completed yetLes parties sont en cours. Compte une dizaine de minutes ; tu peux fermer la page et revenir plus tard.
✓ vert All checks have passedTerminé. Le résultat est en commentaire, plus haut dans la PR.
✕ rouge Some checks were not successfulLe fichier a une erreur (souvent une virgule ou un guillemet), ou un chiffre manque. Clique sur Details : le message nomme l'unité et le champ fautifs, par exemple archer.hp. Corrige comme à l'étape 6.

Le commentaire du robot

Le robot joue 98 parties IA contre IA avec les chiffres actuels (colonne « Avant »), puis 98 avec les tiens (colonne « Après »), et compare :

VictoiresAvantAprès
humains5248 (-4)
isdaris4650 (+4)
draw00
durée moyenne (min)1414

Valeurs d'exemple. « draw » = parties nulles.

Sous ce tableau, Unités produites (clique pour déplier) indique combien de chaque unité les IA ont fabriquées : pratique pour voir si une unité est devenue trop chère pour que l'IA la produise, ou si elle en abuse.

L'objectif

Environ 49 victoires de chaque côté. Un écart de ±5 reste du hasard : il faut un vrai décalage pour conclure.

Les limites

Ce sont des IA, pas des joueurs. Les parties durent 10 à 14 minutes : les unités de fin de partie (sauriens, Char Pégase, Chimère, Discobole) y sont rares. Teste-les aussi en jeu.
Une idée par PRSi tu changes cinq unités d'un coup, tu ne sauras pas laquelle a fait bouger le résultat. Plusieurs PR peuvent être ouvertes en même temps.

6Corriger ou compléter ta proposition

  1. Dans ta pull request, ouvre l'onglet Files changed.
  2. À droite du nom du fichier, clique sur ⋯ puis Edit file.
  3. Modifie, puis Commit changes…. Cette fois, garde le choix proposé : Commit directly to the ta-branche branch (ta branche, pas main).

Le test repart tout seul, et le robot met à jour son commentaire avec les nouveaux chiffres.

Pour abandonner une proposition : bouton Close pull request en bas de la PR. Rien n'est publié.

7Après validation : tester en jeu

Quand ta proposition convient, préviens Max : c'est lui qui la valide (bouton Merge pull request). Ne clique pas sur ce bouton toi-même, même s'il apparaît.

Quelques minutes après la validation, le jeu en ligne utilise tes chiffres : maxbecq.github.io/xcraft. Recharge la page pour être sûr d'avoir la dernière version.

Pour suivre l'historique des changements : github.com/maxbecq/xcraft/pulls (onglet Closed pour les PR terminées).
